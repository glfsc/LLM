## 1. 我的理解（先对齐）

你指出的核心问题是：**系统里同时存在四套互不相同的概念**——「实验」「问卷」「通用问卷」「流程页面」，它们各有一套编辑器、各有一套数据表、各有一套被试端页面。结果是同一件事（比如"一段被试要读的材料"）在不同地方要用不同方式配置，而且实验被写死成了不可改的流程。

重构方向：**把「通用问卷」升级为系统的唯一内核，实验降格为它的一种可复用模板。**

1. **一切拆成题目**，不再有硬编码的"任务信息 / 任务要求 / 反馈 / 量表"槽位。
2. **实验 = 可复用的题目模板**（模板库）。模板内部也是一道道题。
3. **问卷 = 一条链接 + 一列题目**。可逐题插入，也可「插入实验模板」；**插入即展开为普通题目，可逐条修改**。
4. **流程页面取消**：欢迎语、知情同意、结束语、结束说明都变成问卷里的题目（默认已含、默认可空、可删可加）。
5. **两栏侧边栏**：实验管理（模板库）、问卷管理（合并原「通用问卷」）。
6. **通用问卷与实验问卷合并**：一套题目类型、一套编辑器、一套被试端页面、一套数据表。

### 1.1 逐轮反馈的落实

| 你的意见 | 落实方式 |
|---|---|
| 量表本质上是多道打分题 | **删除 `scale` 题型**。量表 = 一道「消息/材料」（指导语）+ N 道「打分题」；另提供「批量插入 N 道打分题」便捷入口 |
| 内容创作本质上是多道问答 | **删除 `creation` 题型**。创作 = 一道「消息/材料」（创作指引）+ 两道文本题（广告语、创作说明） |
| 题目默认全部展开 | 题卡默认展开；点「折叠」才收起为一行摘要；点题卡任意处即选中并展开 |
| 计时默认值默认 0，题目勾选添加限制 | 全局 4 项默认值全为 **0**；每道题按题型列出可用限制，**勾选即启用**并填数值，未勾选用全局默认；**冲突时题目优先** |
| 删掉了手机预做题 | 加回「▶ 从头试填」：手机内完整走一遍（不建会话、不落库），可随时退出 |
| 题目编排改成拖拽 | 题卡左侧拖动手柄，落在目标题上/下半区决定插入前后 |
| 入口退役可以完全删除 | `/survey?c=` 与 5 张 `survey_*` 表**直接删除**，不做兼容跳转 |
| 短文本用填空是对的；**填空高度要能作为参数** | 文本题新增「**输入框高度（行数）**」参数（1 = 单行，>1 = 多行）；由于高度已是参数，**「填空」与「问答」合并为一种「文本题」**，题型从 9 种降为 **8 种** |
| 重构数据库没有问题 | 已确认，按方案重建 |
| 左侧栏复用为题目大纲 | 侧边栏顶部加「菜单 / 大纲」切换：**编辑时同一块区域复用为题目大纲**，可随时切回菜单 |

## 2. 统一题目模型：只有 8 种

| 类型 | 用途 | 关键配置 | 可勾选的计时限制 |
|---|---|---|---|
| `message` **消息/材料** | 任务信息、任务要求、创作指引、反馈文本、量表指导语等纯呈现内容 | 正文（可留空 → 跳过）、图片 | 延迟发出 |
| `gate` **知情同意页** | 进入实验前的伦理门槛 | 正文、勾选文案、按钮文案 | — |
| `debrief` **结束说明页** | 致谢与事后解释（终态页） | 正文 | — |
| `rating` **打分题** | 量表题、满意度等 | 分值区间、锚点 | 作答前强制等待、最短提交、最长作答 |
| `single` **单选** | 注意力检测、反馈来源识别 | 选项、正确答案 | 作答前强制等待 |
| `multi` **多选** | — | 选项、最少/最多 | 作答前强制等待 |
| `text` **文本题** | 广告语、创作说明、人口学、开放式作答 | 必答/选答、**输入框高度（行数）**、字数上限、提示语 | 作答前强制等待、最短提交、最长作答 |
| `rank` **排序** | — | 排序项 | 作答前强制等待 |

**组合示例（不再需要专用题型）**：
- 「目标清晰度测量」= 1 道消息（指导语）+ 5 道打分题
- 「内容创作」= 1 道消息（创作指引）+ 2 道文本题（广告语 1 行、创作说明 2 行）

## 3. 计时模型（题目勾选 + 全局默认）

| 限制 | 说明 | 可用题型 |
|---|---|---|
| 延迟发出 | 内容不立即出现，N 秒后发出（AI 反馈） | 消息 |
| 作答前强制等待 | 需先停留 N 秒才能作答（强制阅读） | 所有需作答的题型 |
| 最短提交时间 | 提交前的最短等待 | 打分题 / 文本题 |
| 最长作答时间 | 到点自动提交已输入内容 | 打分题 / 文本题 |

**取值规则**：题目勾选并填写 → 用题目值；未勾选 → 用问卷（或实验模板）的全局默认值；全局默认值默认全为 **0（无限制）**。

**共用窗口**：把同一套「最短提交 / 最长作答」加在**相邻题目**上且数值相同，它们**共用一个作答窗口**——这样「内容创作」拆成两道题后，仍是一个 3–5 分钟的整体窗口，而不是每题各算一次。UI 在第二道题上明确标注「与上一题共用同一个作答窗口」。

**组别3 / 组别4 的实际配置**（全局默认保持 0，全部按题勾选）：
- 负面反馈（消息）：延迟发出 30 秒
- 注意力检测（单选）：作答前强制等待 40 秒
- 广告语 + 创作说明（文本题 ×2）：最短提交 180 秒 / 最长作答 300 秒（共用窗口）

## 4. 两栏侧边栏 + 编辑期大纲

```
侧边栏顶部：[ 菜单 ] [ 大纲 ]        ← 同一块区域，随时来回切换
├─ 菜单模式：实验管理 / 问卷管理
└─ 大纲模式（编辑实验或问卷时默认）：
     模板信息 / 计时默认值 / 题目编排（37 道）   ← 点击跳转到对应区块
     题目条目列表（类型图标 + 标题 + 已启用限制数量）
        · 点条目 → 选中该题、自动展开、编辑器滚动到该题
        · 点题卡 → 大纲对应条目高亮（双向联动）
        · 拖动排序 / 插入 / 删除 → 大纲同步更新
```

编辑页其余交互（实验与问卷完全一致）：
- **题目默认全部展开**；点「折叠」收起为一行摘要；点题卡任意处即选中并展开，右侧预览跟随。
- **拖拽排序**：题卡左侧手柄拖动。
- **插入题目**：8 种题型单题插入；「批量插入 N 道打分题」；「插入实验模板」整组复制（带「来自模板」分组标识与「整组删除」，复制后逐条可改）。
- **插入位置**：自动落在「开头页（欢迎语 / 知情同意）」之后、「收尾页（结束语 / 结束说明）」之前。
- **从头试填**：手机内逐步呈现并作答，实时回显，不建会话不落库。

**新问卷默认包含**：欢迎语（消息，空）、知情同意页、结束语（消息，空）、结束说明页 —— 均可编辑、删除、拖动。

## 附：v6.3 增量（实施后的 9 条体验反馈）

设计定稿后按实际试填反馈又做了一轮交互打磨，**模型与数据契约不变**，只改呈现与交互：

| 反馈 | 落实方式 |
|---|---|
| 1. 要对话式、不要回答堆叠 | 提交后卡片**就地保留**题干与控件（只读），去掉「评分：5 分」这类回答气泡 |
| 2. 题目都要手动提交 | 删除「点选即提交」；统一走卡内「确认提交 / 提交创作」 |
| 3. 下方不要重复的题目 | 单题作答只在卡片内进行，控件不再重复渲染题干（多子题的题组除外） |
| 4. 图二底部多余按钮 | 知情同意/结束说明改为**屏内勾选 + 屏内按钮**，底部操作区整体删除 |
| 5. 继续后应落在题目开头 | 推进到下一题时把新题卡片滚到可视区**顶部** |
| 6. 有限制的题也应能填写 | 门控期间控件照常可用，**只有提交按钮置灰**并显示倒计时 |
| 7. 系统输入要思考 + 流式，且不能暴露剩余时间 | 新增呈现节奏参数 `thinkMs`（思考时长）/ `typeMs`（流式速度），**全局默认 + 单题覆盖**；延迟反馈只显示「对方正在输入…」 |
| 8. 图三底部空白 | 同 2 / 4：底部不再有任何作答区 |
| 9. 编辑区文本域溢出 | 全部文本域**随内容自动增高**（`overflow:hidden`，取消内部滚动） |

试填（手机内）同步重做：屏内卡片作答、消息播完自动推进、提交按钮同样「已作答 + 门控到时」才亮起。

**试填空白屏修复**：被试端会跳过「留空」的消息（如问卷默认的欢迎语 / 结束语），但试填最初没有跳过，遇到这类题目会停在空白屏不再推进——现在试填也会跳过空消息，并在走查里增加了「从头试填必须跑到试填结束」的回归校验（20× 倍速，约 35 步）。

## 附：v6.4 增量（第二轮体验反馈）

| 反馈 | 落实方式 |
|---|---|
| 1. 回答限制的倒计时放到题目右上角，限制结束后变成回答倒计时 | 卡片标题栏新增倒计时徽标：门控期「阅读中 · N 秒后可提交」/「N 秒后可提交」→ 门控结束切换成「作答计时 · 剩余 N 秒」；提交后撤掉。被试端与手机试填一致 |
| 2. 已回答题目的折叠按钮还是没有 | 被试端原本就有（✓ 已提交 + 折叠）；**试填**的已答卡片此前缺失——补齐折叠/展开按钮，走查断言「每张已答卡片都有折叠按钮」 |
| 3. 单选 / 多选在试填里每个选项都是空白 | 题库里选项存的是纯文本数组，服务端发给被试端时转成了 `{value,label}`，但**管理端试填/预览直接读了 `opt.label`** → 空白。统一加 `optList()` 归一化（自动补 `A．` 前缀），试填与实时预览都正常 |
| 4. 知情同意确认后内容可以清空（不在实验内） | 试填里 gate 一经确认即从屏内移除；结束说明页保留 |
| 5. 三栏（菜单 / 编辑 / 手机）要能拖动调整，分割线默认浅色、悬停高亮 | 三栏之间各加一条分隔线：默认浅色细线，悬停/拖动高亮，按住拖动调宽，双击复位；宽度记在 localStorage |
| 6. 菜单/大纲栏要折叠与缩放按钮，放在表头「实验对话系统」右侧 | 表头右侧加 `−` / `＋`（40px 一档，180–460px）与 `«` 折叠；折叠后左上角 `»` 一键展开，状态持久化 |
| 7. 链接怎么区分用户 / 并发怎么办 | 见《实验对话系统-方案文档》§4 与「分发与并发」：一台设备一份会话（localStorage 记 session id + 服务端恢复窗口），每人全程约 30 次小请求、零轮询，单机 300 并发≈396 QPS；结束页补「我是新被试，重新开始」按钮，便于同一台设备换人 |
