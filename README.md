# 实验对话系统

「对话式问卷」实验平台：被试在手机上像聊天一样逐题完成实验（材料 → 量表 → 创作 → AI 反馈 → 再创作），
研究者在管理端编排题目、手机端所见即所得地预览、看数据、导出 Excel。

**零第三方依赖 · 单进程 · 单文件 SQLite · 前端无构建** —— 一台电脑离线就能跑完整场实验，
笔记本开个热点、手机扫码即可开始收数据。

> 本分支 `pilot/lan-qrcode` = **局域网预实验版**，额外带「管理端各组二维码（可保存图片）+ 手机扫码连接页 + 双击启动的便携包」。
> 不需要局域网部分（部署服务器做正式实验）用 `main` 分支，其余功能完全一致。

## 项目特色

- **零依赖、零安装**：用 Node 内置 `node:sqlite` 当数据库，不跑 `npm install`、不装数据库；`npm start` 即启动。
  便携包还内置 `node.exe`，目标电脑**不需要装任何软件**。
- **手机扫码开做**：双击 `启动预实验.bat` → 自动起服务并打开登录页；登录后在管理端「问卷管理」生成二维码：
  右上「手机入口二维码」用于进系统入口页，每行问卷的二维码让被试**扫码直达对应组别的作答页**，并可一键**保存成海报式 PNG**
  （问卷/组别名 + 二维码 + 网址）打印或发群。重复双击不会冲突：会先结束没退干净的旧实例；端口被别的程序占用则自动换一个空闲端口，
  二维码与管理入口都跟着走。
- **一切皆题目**：实验 = 可复用的**题目模板**；问卷 = 一条链接 + 一列题目。插入模板即整组复制，复制后随便改。
- **10 种题型**：打分 / 单选 / 多选 / 文本 / 排序 / 题组，以及材料消息、知情同意页、阅读确认页、结束说明页。
  文本题带一个二级形态「**需输入指定内容**」：被试必须在底部输入框里输入指定内容（如「我已完成阅读」）才发送得出去，
  空或不符时只在输入框上方提示（提示文案可自定义，默认「答案错误」），这一笔不落库、也不进聊天流；
  断言在服务端做，标准答案不下发被试端。选入口在「插入题目」的二级菜单里。
- **打分题可单独重做**：打分题默认带「**允许重做**」参数（题目参数区可逐题关闭）——已提交的打分题卡片上是「重做」按钮，
  点它只把这一张卡片临时变回可改状态（原分保持选中），改完点「确认提交」才落库；没有取消路径，点了重做就必须提交
  （想保留原分数就重新选回原值再交）。当前题、倒计时、进度、聊天流都不受影响，数据只留终值（就地更新那一行，不产生重复作答行）。
  卡片状态徽标只有两种：重做中 =「未提交」（黄），其余 =「✓ 已提交」（绿）。同屏只允许一张卡片在重做中；
  **刷新点 / 交卷前**会先把页面带到未提交的卡片并弹窗点名（⚠ 徽标 + 「还未提交的题目：第 N 题」），
  回卡片提交后流程自动继续——弹窗不替被试提交。刷新 / 重进后旧的已答卡片不再提供重做（清屏点之前的题也不再呈现，设计如此）。
- **计时门控服务端权威**：强制阅读 N 秒、最短提交、最长作答到点自动提交、题目呈现前清屏；
  相邻同参数的题共用一个作答窗口；提前提交由服务端直接拒绝，不靠前端计时，也不产生轮询。
- **AI 思考面板**：负反馈正文之前先流式「思考」一段，与打字机消息同一节奏；
  时长默认 **20 秒**（在「思考过程」行里改，上限 60 秒），思考结束、正文开始前另有一行「思考已完成」，
  思考内容用**五号 14px**（比正文小四小一档，读起来是个「旁白」）。
  **播完即锁死**：思考稿输出完，正文容器连同文本一起从 DOM 移除，头部只剩一行不可点击的「✨ 已思考（用时 N 秒）」，
  刷新 / 重进会话也只会重建这一行 —— 被试没有「再看一遍」的入口（研究者侧在管理端答题记录里仍可回看）。
  时长就是**弹出速度**：思考稿按「剩余毫秒 ÷ 剩余字数」铺字（约 40 字/秒，与 LLM 流式输出同量级），
  到点正好写完、末尾不再干等 —— 想把 20 秒改成 15 秒 / 30 秒只改这一个参数，不必改稿。
- **反馈正文与评价标准对齐**：四点按组别3「评价标准」的四个维度组织（品牌契合度 → 原创性 → 可记忆性 → 可延展性），
  按研究者口径**不写分值**；两组共用同一份（组间只差任务要求两处）。
  改这段文字要守住注意力检测题（题干问「哪一个选项没有在反馈中出现」，正确答案是「格式不符合要求」）：
  正文必须保留「可延展性不足」与「与品牌主张的关联停留在表层」、且不得出现另外两个选项的字样，`npm run check` 盯着这条。
- **连发消息不再刷空白**：流式输出时「还没输出的部分不占高度」——骨架里的换行与还没写到的段落先隐藏，
  写到那一行才显形；于是跟随滚动的视口始终贴在**正在输出的那行字**上，不会跳到一片空白行上（内容也不会「从上方流下来」）。
- **正文一律小四 16px**：被试端（AI 消息、被试自己的气泡、题干、作答输入框、同意页文字）与管理端富文本编辑器的「正文（默认）」
  都是 16px；材料里的小节标题是四号 19px（由 `db.js` 的 `body16` / `materialHtml` 统一生成，种子与线上一致）。
  同样为 16px 的还有：管理端的**题卡标题 / 折叠摘要 / 思考过程 / 层级与批量数量输入**，被试端的**勾选文案 / 整页按钮 / 编号字段名 / 选项按钮 / 排序项 / 题组子题标题**。
  编辑页里与题目内容相关的**字段名与字段内容**（大纲标题 / 标准答案 / 输入框提示语 / 选项 / 打分题参数等）也是小四，
  以及参数区的参数名、参数数值与单位；**AI 思考稿**（`.param-think`）同为 16px。
  只有填写提示、参数说明等界面小字保持 10.5–12.5px 的层次；左侧大纲标题仍是 12px（为了同宽下多看几个字）。
- **全卷视图工具条吸顶**：滚长卷时字号 / 加粗那条工具条钉在顶部操作条下面（`showFullView` 里量高度写 `top`，
  改字号 / 加粗不必再滚回开头）。粘贴自 Word 的编号列表（`<![if !supportLists]>1.<![endif]>`）会被清洗成正常文字，
  条件标记摘掉、编号保留，`&nbsp;` 之类实体还原成空格，不会在正文里留下乱码。
- **一键「显示全卷」**：编辑页右上角按钮（保存问卷左边）把每道题的正文拼成一份全文，题与题之间一条分割线，
  每题上方一行灰色题目标识（不可编辑、不参与切分）——通读全卷、全选统一改字号 / 加粗都在这一个编辑器里做；
  切回分题时按分割线切分写回每题，分割线数量对不上会拒绝切回并提示，不会把整卷写进一道题。
- **编辑期大纲有记性**：进入编辑页时大纲**默认折叠到最高层**（只显示最大级别，下属不显示）；
  点行 / 滚到某一题会自动展开它的上级。退出时的**展开状态与所在题目**记在本机（按问卷 / 模板分开记），
  下次进入直接落回上次看到的那道题，大纲也是离开时的样子。
- **管理端手机预览**：右侧是真被试端 iframe（同源同代码），支持 1×/5×/10×/20× 倍速、拖进度条或输题号跳题、一键「重做」；
  预览不建会话、不落库。
- **数据即用**：每次作答都带呈现/作答时间戳与耗时落库；一键导出 Excel，三个 sheet：
  「汇总（一行一被试，统计用精简表：编号 + 各量表逐题原始分 + 两次作品文本 + 选择题答案与对错；
   Times New Roman 11、表头加粗居中换行）」、
  「逐题作答（一行一被试：编号 + 完成状态 + 每题答案，纯答案不带时间）」、逐题明细（含呈现/作答时间与耗时）。
- **自检与护栏**：`npm run check` 平台与内容双自检、`npm run shots` 无头浏览器全流程截图走查、
  `npm run probe` 并发探针、`npm run sync-groups` 强制两个组别只差「任务要求」两处文本。
- **容错**：逐题提交 + 断网自动重试；刷新/关页可在恢复窗口内续做；同一设备按进入顺序自动编号；超时无操作自动作废并释放设备。

## 快速启动

### 1. 实验现场：局域网便携包（本分支推荐）

```text
双击  启动预实验.bat
→ 自动启动服务并打开登录页（admin / admin123，首次请改密码）
→ 管理端「问卷管理」：点右上「手机入口二维码」或每行问卷的二维码图标
→ 弹窗里「保存图片」得到海报式 PNG → 打印张贴 / 发到群里
→ 手机连同一个 WiFi（或电脑/手机热点）→ 相机扫码 → 直达作答页
```

- 二维码里的地址自动取「手机能打开的地址」：管理端用 `localhost` 打开时用本机局域网 IP，用域名（含公网部署）打开时用当前域名；
  被试扫码**直达作答页**，不用再粘贴链接。地址栏/链接框里显示的被试链接同口径。
- 电脑端管理入口 `http://localhost:3000/admin`，默认账号 `admin` / 密码 `admin123`（**请尽快改掉密码**）。
- 目标电脑无需安装 Node.js：便携包内已带 `node.exe`；重复双击也不会冲突（会自动结束没退干净的旧实例）。
- 打包便携包：`npm run portable` → `dist/预实验便携包.zip`（内置 node + 仅运行必需文件，是唯一分发件）。
  包内数据库取自当前 `data.db` 的**只读快照**：实验模板 / 问卷 / 账号原样带走，只清空被试数据（会话、作答、对话消息），
  不给实验人员留下历史被试记录；打包过程不改动开发机上的 `data.db`。
  想发「从代码种子重建的库」，先在开发机跑 `npm run reset-db` 再打包。
- 现场排障（热点怎么开、防火墙放行、AP 隔离、手机连不上四步检查）见 [实验人员须知.txt](实验人员须知.txt)。

### 2. 本机开发 / 服务器

```bash
node server.js     # 等价 npm start；默认端口 3000，可用环境变量 PORT 覆盖
```

- 首次启动自动建库并灌入种子数据：2 个实验模板（组别3 / 组别4）+ 2 份预设问卷，管理员 `admin` / `admin123`。
- **账号登录规则（一账号单设备）**：同一账号同时只允许一台设备在线 —— 在别处登录、本人改密、或管理员重置该账号密码，先前设备上的登录会立即失效（回登录页并提示原因）；登出是持久化生效的，重启服务不会复活旧登录态。
- 入口：`/` 登录页（也可凭链接直接填问卷，无需登录）· `/admin` 管理端（问卷管理页可生成各组二维码并保存图片）· `/chat?q=<8位短码>` 被试端 · `/connect` 手机扫码页（手动备用，二维码以管理端为准）。
- 部署到服务器（域名 + HTTPS + systemd）见 [DEPLOY.md](DEPLOY.md)。

## 被试端会经历什么（预设问卷）

```text
欢迎语（小A 自述）→ 知情同意页（勾选同意 + 填被试编号）→ 任务信息 → 任务要求
→ 阅读材料确认（输入「已完成阅读」才能继续）
→ 目标清晰度 5 题 → 创作指引 → 广告语创作（120 秒后才可提交 / 480 秒到点自动提交）
→ AI 负面反馈（自称「小A」；先思考面板 20 秒，再流式输出正文）→ 用户阅读确认反馈（输入「已完成阅读」，之前强制停留 30 秒）
→ 注意力检测 1 题 → 反馈来源识别 1 题
→ 反馈公平性 6 题 → 反馈效价感知 2 题 → 元过程 5 题（进入这一节先清屏）→ 任务过程 4 题
→ 第 8 节「再次完成一模一样的任务」（指导语 + 任务信息 + 任务要求）→ 再创作 1 题
→ 结束说明页（含欺骗的事后解释）
```

- **组别3** = 目标清晰度**高**（任务要求含 6 条要求 + 100 分评价标准：品牌契合度 30 / 原创性 25 / 可记忆性 25 / 可延展性 20）；
  **组别4** = 目标清晰度**低**（2 条极简要求）。两组只差这两处「任务要求」文本，其余逐字段相同，
  由 `npm run sync-groups`（默认只预览，`--apply` 才写入）强制保证：脚本按 `seed-content.js` + `db.js` 的种子内容
  重建两份预设问卷与两个实验模板，并逐字段复核。
- 每份预设问卷共 42 条内容 = **28 道题号题** + 14 条材料与页面环节（模板 40 条，外加头尾的知情同意页与结束说明页）；
  量表题的题干与大纲标题都带序号（1. / 2. …）。

## 内容模型：一切皆题目

| 概念 | 说明 |
| --- | --- |
| 实验模板 | 可复用的题目组合（一套题），如「组别3」「组别4」。问卷「插入实验」时整组复制，之后逐条改；模板删除不影响已建问卷 |
| 问卷 | 一条链接 + 一列题目。链接是 8 位不透明短码（不含 0/1/l/o），被试看不出组别 |
| 题目层级 | 1–4 级，只用于管理端大纲分组，不影响被试端呈现 |
| 会话 | 被试打开链接即建会话，题目与计时**快照**进会话：之后改模板/问卷不影响进行中的被试 |

## 项目结构

```text
server.js              HTTP 服务端：静态资源 + 全部 API + 会话状态机（计时门控 / 预览会话 / 鉴权 / 局域网信息与二维码）
db.js                  数据层：建表、种子内容、全部 SQL 访问函数（node:sqlite，WAL 模式）
xlsx.js                零依赖 Excel 导出（手写 OOXML + deflate 打包）
seed-content.js        实验材料文案种子：任务信息、反馈正文、思考稿、量表题目
public/
  index.html           登录 / 注册 / 凭链接填问卷
  admin.html           管理端外壳（hash 路由 SPA）
  chat.html            被试端外壳
  connect.html         手机扫码连接页模板（占位符由服务端替换）
  assets/admin.js      管理端：问卷/实验编辑器、题目编排、手机预览、数据页、用户与设置
  assets/chat.js       被试端：消息流、10 种题型控件、门控倒计时、恢复与重做、预览桥
  assets/richtext.js   富文本工具（浏览器与 Node 共用同一份）
vendor/qrcode.js       二维码生成（qrcode-generator，MIT）
scripts/               启动器、打包、自检、探针、种子与模拟数据工具（见下表）
data.db                运行时数据库，首次启动自动生成（不入库）
DEPLOY.md              服务器部署文档
实验人员须知.txt        便携包现场使用与排障须知
design/ demand/        设计稿与重构方案 / 原始实验材料（docx）
```

开发与自检脚本（`scripts/`）：

| 脚本 | 作用 |
| --- | --- |
| `pilot-start.js` | 预实验启动器：端口冲突自愈、自动打开登录页（由 `启动预实验.bat` 调用） |
| `build-portable.js` | 打包 `dist/预实验便携包.zip`（内置 node 单成品；数据库取当前库快照并只清空被试数据） |
| `check-platform.js` | 平台行为自检（题型、门控、预览、导出等，带夹具，不依赖实验内容） |
| `consistency-check.js` | 当前内容配置自检（预设问卷的题数、量表、反馈正文等） |
| `capture-shots.js` | 无头浏览器全流程走查截图 + 断言 |
| `load-probe.js` | 并发与延迟基线探针 |
| `simulate-subjects.js` | 走真实被试端接口灌模拟数据（`--n 20`） |
| `sync-group-content.js` | 以组别4 为基准同步组别3，只保留「任务要求」两处差异 |
| `seed-thinking.js` | 把反馈题同步成种子的最新版（正文 / 排版 / 思考稿 / 思考时长；`--dry` 只看不动） |
| `seed-presets.js` / `reset-db.js` | 重建预设问卷 / 删库重建 |
| `sync-group-content.js` | 按种子内容重建「组别3 / 组别4 预设问卷 + 两个实验模板」（默认只预览，`--apply` 备份后写入） |
| `lib/` | 自检用的直连数据库、HTTP 客户端、会话驱动器、xlsx 读取 |

## 说明

- 运行环境 Node.js ≥ 22.13.0（用到内置 `node:sqlite`）；用便携包则无需自备 Node。
- 实验材料（题目、反馈正文、思考稿、量表指导语）来自 `seed-content.js` + `db.js` 的种子；改完种子想让线上预设问卷/模板跟上，
  有两条路：**只改反馈题**（改反馈正文 / 思考稿 / 思考时长时用）跑 `npm run thinking`（幂等，先备份 `data.db`）；
  **整份重建**（题目结构也变了）跑 `npm run sync-groups -- --apply`。两条路之后都跑 `npm run check` 自检。
- 字号 / 排版的唯一出处：正文小四 16px、小节标题四号 19px（`db.js` 的 `body16` / `materialHtml`）；
  被试端 CSS 的正文默认也是 16px（`public/assets/chat.css`），管理端编辑器默认 16px（`.rich-edit`）。
- 两个组别各对应一份问卷链接，由研究者按批次分发决定谁进哪组；系统不做一人一链，也不做防重复参加。
- 数据全部在 `data.db`（WAL 模式，另有 `-wal`/`-shm` 伴生文件）：可管理端导出 Excel，也可停机后整库取回。
